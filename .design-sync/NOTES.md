# design-sync notes — dataleap-design-system

- This repo is a private Vite APP, not a library: no `main`/`module`/`exports`, no `.d.ts` build. The converter runs from a committed hand-made entry `.design-sync/entry.ts` (re-exports every `src/components/ui/*.tsx` family + theme-provider), passed via `cfg.entry`. If a new component file is added to `src/components/ui/`, regenerate/extend `entry.ts` AND add the family's primary export to `cfg.componentSrcMap`.
- Component cards are ONE per shadcn family (59), pinned in `cfg.componentSrcMap`; the other ~280 subcomponent exports still ship in the bundle (357 exports on `window.ShadcnUI`) and are documented per-family in `.design-sync/ds-docs/`.
- `direction.tsx` (DirectionProvider) and `theme-provider.tsx` (ThemeProvider/useTheme) ship in the bundle but deliberately get no card.
- CSS comes from the app's compiled Tailwind v4 build: `cfg.buildCmd` runs `pnpm build`, then copies `dist/assets/index-*.css` → `.design-sync/.cache/css/app.css` while rewriting `url(/assets/…)` → `url(./…)` (Vite emits absolute asset URLs; without the rewrite no woff2 ships and validate fires FONT_DANGLING). The woff2 files are copied alongside so `extractFonts` finds them.
- IMPORTANT css ordering: Tailwind v4 auto-content-detection scans the repo (previews in `.design-sync/previews/` are committed, hence scanned). Any Tailwind class used ONLY in a preview gets compiled in on the NEXT `pnpm build`. Preference, not a rule (relaxed 2026-09-17): previews use inline styles for layout glue so incidental classes don't leak into the bundle, but a preview MAY deliberately use a Tailwind class to make a documented usage pattern ship — e.g. `previews/Progress.tsx` carries `[&_[data-slot=progress-indicator]]:bg-warning` on purpose so the threshold recipe's utility exists in `_ds_bundle.css`. When you rely on this, say so in the preview with a comment.
- Known render warns (recorded so re-syncs don't read them as new — check the label on each, they are NOT all benign):
  - `[TOKENS_MISSING]` 12 vars: `--toast-*`, `--accordion-panel-height`, `--drawer-swipe-*`, `--nested-drawers` — all set at runtime by base-ui components (inline style/JS), never defined in stylesheets. Expected.
  - `[GRID_OVERFLOW]` — **RESOLVED 2026-07-25.** Was 28 components of debt left by the first sync (which fixed only Card + Dialog/AlertDialog/Sheet/Drawer). Fixed by adding 28 entries to `cfg.overrides`: 21 `{"cardMode":"column"}` + 7 `{"cardMode":"single","primaryStory":…}`. Warn count went 29 → 2. Only `Progress` still flags; see the false-positive bullet below.
  - `[GRID_OVERFLOW]` on **`Progress` only — known FALSE POSITIVE, leave it.** base-ui's `ProgressIndicator` is positioned outside `ProgressTrack` and clipped by the track's `overflow-x-hidden`, so the geometry probe reads "content outside its cell" and classifies it `escape` even though nothing is visually outside. Its real problem was width, so it got `{"cardMode":"column"}` (NOT the suggested `single`, which would have dropped 2 of its 3 stories for nothing) — verified by screenshot that the labels no longer crop. `column` cannot clear an `escape` classification by construction, so this warn is permanent. Do not "fix" it.
- `cfg.overrides.Card = {cardMode: column}` — Basic/WithForm stories are 360px wide, overflow grid cells.
- Radius tokens: `src/index.css` defines `--radius-sm|md|lg|xl|2xl|3xl|4xl`; the shipped `_ds_bundle.css` currently defines **`--radius`, `--radius-sm`, `--radius-md`, `--radius-lg`, and `--radius-xl`**. The 2026-07-24 correction over-corrected: it dropped `lg` too, and `conventions.md` claimed "those three are all the shipped stylesheet defines" until 2026-07-25. `--radius-lg` has in fact shipped all along (`rounded-lg` is used by tabs / input-group / button-group / input-otp / chart / popover / hover-card / field / resizable). Verify with `grep -o -- '--radius-[a-z0-9]*:' ds-bundle/_ds_bundle.css | sort -u` rather than reasoning about `src/index.css` — the shipped file is the only authority.

## Re-sync risks

- **Renaming `cfg.pkg` silently destroys every preview card — and the verdict still says `ok: true`.** `lib/story-imports.mjs` builds `pkgRx` from the *literal* `cfg.pkg` string and rewrites matching imports to `window.ShadcnUI`. All 59 `.design-sync/previews/*.tsx` import from `"<pkg>"`, so the moment `cfg.pkg` changes and the previews don't, esbuild can't resolve the specifier, all 59 preview compiles fail, and every component silently falls back to the typographic floor card. **The re-sync verdict does not catch this**: `sourceKeyFor` hashes the preview *bytes* and the config *slices*, and `cfg.pkg` is in neither — so `sourceKeys` all hold and verification reports "59 unchanged" over a bundle whose cards are all placeholders. Happened 2026-07-25 (commit e6781a3 renamed shadcn-stock-design → dataleap-design-system); caught only because 12 `[RENDER_BLANK]` + 1 `[RENDER_THIN]` warns appeared that this file didn't list. **If you ever change `cfg.pkg`, grep the whole repo for the old name in the same commit** — it lives in `previews/*.tsx` (functional) AND `ds-docs/*.md` (they ship as the `.prompt.md` the design agent reads) AND `conventions.md`'s example. Fast check after any build: `grep -c "preview build failed" <driver log>` must be 0, and the render summary must read `59/59 previews render cleanly`, not `N showing the typographic floor card`.

- **`DESIGN.md` is NOT a sync input — its rules are mirrored by hand into `conventions.md`.** The sync only reads: `entry.ts` → `src/components/ui/*.tsx`, `buildCmd` → `src/index.css`, `.design-sync/ds-docs/`, and `.design-sync/conventions.md` (`readmeHeader`). `DESIGN.md` sits at the repo root and matches no `guidelinesGlob` default, so writing a rule there and running a sync propagates **nothing**. As of 2026-07-25 the "Design rules" section of `conventions.md` mirrors DESIGN.md's Rules section (semantic tokens / one accent / one radius knob / one typeface / dark-mode value flip / density). **Editing DESIGN.md now requires editing `conventions.md` in the same commit**, or the design agent keeps being told the old rule. Alternative if this mirror becomes a burden: set `cfg.guidelinesGlob` to include `DESIGN.md` so it ships verbatim to `guidelines/` — but note `conventions.md` is the channel that actually gets inlined into the agent's prompt, so the distilled mirror is what the agent reliably reads.

- `cfg.entry` (`.design-sync/entry.ts`) is hand-maintained — silently misses components added to `src/components/ui/` after 2026-07-24. On re-sync check `ls src/components/ui | wc -l`: **60 files = 59 carded families + `direction.tsx`** (DirectionProvider, deliberately card-less, so it is NOT in `componentSrcMap`). A count of 60 is the expected steady state, not a miss; 61+ means a genuinely new component. (An earlier note said "59 files" — that counted mapped families, not files, and cost a re-verification pass. Diff the dir against `cfg.componentSrcMap` rather than trusting the raw count.)
- Compiled CSS is a byproduct of the app build; if the app's `src/index.css` or Tailwind version changes, all component styling shifts — re-verify visually, don't trust carried grades blindly for brand changes (grades key on preview sources, not CSS).
- Playwright cache: chromium installed 2026-07-24 via `.ds-sync` npm playwright (repo pins none).

## Preview-authoring recipes (folded from wave 1 learnings, 2026-07-24)

- **base-ui composition uses `render={<Button/>}`**, not Radix `asChild`. Tooltip needs `TooltipProvider`. DrawerContent throws outside `Drawer`.
- **Bare `*MenuLabel` outside a Group crashes the whole React root blank** (base-ui `MenuGroupContext is missing`) — always wrap DropdownMenuLabel/ContextMenuLabel/MenubarLabel in `*MenuGroup`/`*MenuRadioGroup`. The classic shadcn "bare label atop Content" pattern does NOT work in this port.
- Open-state recipes: DropdownMenu `defaultOpen modal={false}`; MenubarMenu `defaultOpen`; NavigationMenu root `defaultValue` + item `value`; ContextMenu needs a mount-time dispatched `contextmenu` MouseEvent (see previews/ContextMenu.tsx).
- **recharts is bundled twice** (once in _ds_bundle.js, once per preview) → ChartContainer's ResponsiveContainer context never reaches preview-authored chart elements; charts silently blank. Workaround in previews (and guidance for designs): explicit width/height on the chart element, import Tooltip/Legend from recharts with the kit's ChartTooltipContent/ChartLegendContent as `content`, `isAnimationActive={false}`. Proper fix: externalize recharts in preview-rebuild like react.
- **react-resizable-panels v4**: `direction` prop renamed `orientation` (shadcn docs examples silently no-op). `aria-[orientation=vertical]:flex-col` in resizable.tsx is dead code in v4 (harmless).
- `--chart-1…6` are the DataLeap six-color categorical scale (green / blue / amber / violet / rose / teal, hex in `src/index.css`); the earlier "grayscale stock kit" note predates the brand pin and is obsolete.
- Toast static capture: per-cell `createToastManager()` + `manager.add({timeout:0})` in ref-guarded useEffect; compose ToastProvider+ToastViewport (position absolute inside sized div), render list via `useToastManager()`; Toaster's fixed viewport unusable in cards; ToastIcon/ToastList not exported.
- Sidebar static capture: `collapsible="none"` (offcanvas default is hidden/fixed); override `min-h-svh` with inline height.
- ComboboxInput style lands on the inner input — constrain width with a wrapper div around the whole Combobox. InputOTP (input-otp v3) is controlled-only: `value` + no-op onChange. SelectValue takes `placeholder`; pass `items` to Select root for closed-trigger label.
- Sheets reserve tall cells with top-aligned content — empty space below a story is normal, not collapse.
- Empty renders `border-dashed` but no border width — a framed empty state needs caller-supplied border. Collapsible is unstyled by design; style triggers via `render` prop (e.g. Button).
